# Tech Stack Used

## A. Core Framework and User Interface

### Streamlit (`streamlit==1.60.0`)

**Role**

Streamlit serves as the frontend framework and user interface for the application.

**Why it was chosen**

Streamlit allows the entire application to be built using Python without requiring a separate frontend framework such as React or Angular. This significantly reduces development time while providing responsive widgets, file uploads, layouts, and download functionality out of the box. It is particularly well suited for rapid prototyping and data-focused applications.

**How it is used in byePII**

- Uploads PDF, DOCX, and TXT documents.
- Provides checkboxes for enabling or disabling redaction policies such as Names, Emails, Phone Numbers, Addresses, Organizations, and Images.
- Displays summary metrics showing the number of detected and redacted entities.
- Allows users to download the anonymized document and generated reports.

## B. Document Extraction and Rewriting

### PyMuPDF (`pymupdf==1.28.0`)

**Role**

PyMuPDF is responsible for PDF parsing, text extraction, page rendering, and visual redaction.

**Why it was chosen**

PyMuPDF offers excellent performance and a feature-rich API compared to alternatives such as `PyPDF2` and `pdfplumber`. It not only extracts text efficiently but also provides access to text coordinates, renders pages as images for computer vision tasks, and supports writing directly back to the PDF canvas.

This makes it an ideal choice because a single library handles both text processing and image-based redaction.

**How it is used in byePII**

- Extracts text from every page before PII detection begins.
- Identifies the coordinates of sensitive text for accurate redaction.
- Renders PDF pages as images for OpenCV-based logo and ID card detection.
- Applies permanent visual redactions using grey rectangles drawn directly onto the document.


### python-docx (`python-docx==1.2.0`)

**Role**

Reads, modifies, and rewrites Microsoft Word documents.

**Why it was chosen**

`python-docx` is the standard open-source library for manipulating DOCX files without requiring Microsoft Word. It preserves the document structure while allowing direct access to paragraphs, tables, runs, and formatting.

This makes it possible to replace sensitive information without affecting the original layout of the document.

**How it is used in byePII**

- Reads paragraphs, tables, and text runs.
- Replaces detected PII with synthetic values generated by Faker.
- Preserves formatting such as fonts, styles, spacing, and alignment after replacement.

## C. Natural Language Processing and PII Detection

### Presidio Analyzer (`presidio-analyzer`) and spaCy (`spacy==3.8.14`)

**Role**

Microsoft Presidio performs PII detection while spaCy provides the Natural Language Processing engine used for Named Entity Recognition (NER).

**Why they were chosen**

These two libraries complement each other well.

Microsoft Presidio combines rule-based recognizers, lookup lists, and NLP models to identify sensitive information across different document types.

spaCy is one of the fastest and most reliable NLP libraries available. The `en_core_web_sm` model recognizes entities such as people, organizations, locations, and dates by understanding context instead of relying only on fixed patterns.

Using both libraries together improves detection accuracy and reduces the number of missed entities.

**How they are used in byePII**

- Load the spaCy language model inside the Presidio Analyzer.
- Scan extracted document text for names, organizations, dates, and locations.
- Pass the detected entities to the redaction pipeline for further validation and replacement.

## D. Synthetic Data Generation

### Faker (`Faker==40.35.0`)

**Role**

Generates realistic synthetic data to replace sensitive information.

**Why it was chosen**

Replacing confidential information with realistic values produces documents that remain readable and structurally correct. This approach is often more useful than replacing every entity with generic placeholders such as `[REDACTED]`.

Faker supports names, email addresses, phone numbers, addresses, companies, and many other data types, making it well suited for document anonymization.

**How it is used in byePII**

- Generates replacement values based on the detected entity type.
- Maps labels such as `PERSON` to `faker.name()` and `EMAIL` to `faker.email()`.
- Maintains a mapping cache so that when **Preserve Consistency** is enabled, the same original value is always replaced with the same synthetic value throughout the document.

For example, every occurrence of **"Lokesh Shah"** will always become **"Vikram Malhotra"** within the same document instead of changing every time it appears.

## E. Data Analysis and Output Reporting

### Pandas (`pandas==3.0.5`)

**Role**

Processes structured data and generates audit reports.

**Why it was chosen**

Pandas is the industry standard library for working with tabular data. It simplifies the creation, manipulation, and export of structured datasets into formats such as CSV, Excel, and JSON.

For byePII, this makes audit report generation straightforward and efficient.

**How it is used in byePII**

- Stores detected entities in structured DataFrames.
- Generates audit reports containing detected values, labels, and replacement information.
- Exports reports as CSV and JSON files for future verification and compliance.

## F. Image Processing and Computer Vision

### OpenCV Headless (`opencv-python-headless`) and Pillow (`pillow==12.3.0`)

**Role**

OpenCV performs the computer vision operations used for image detection, template matching, and visual redaction, while Pillow provides lightweight image loading and basic image manipulation.

**Why they were chosen**

These two libraries work together to handle the image processing pipeline efficiently.

**OpenCV Headless** is optimized for high-performance image processing and mathematical operations on pixel arrays. The headless version removes graphical dependencies, making it ideal for deployment on Linux servers and cloud environments where display drivers are unavailable.

**Pillow** is Python's standard image processing library. It provides a simple interface for loading, converting, and manipulating images before or after OpenCV processing.

Together, they provide everything needed to detect sensitive visual elements and anonymize them without introducing heavy machine learning dependencies.

**How they are used in byePII**

The image processing pipeline performs three main tasks.

**Multi-Scale Template Matching**

The system searches each page for known logos and identity cards using `cv2.matchTemplate` with the `cv2.TM_CCOEFF_NORMED` similarity metric. The search is repeated across approximately fifteen image scales, allowing the same logo to be detected even if it appears larger or smaller within different documents.

**Direct Similarity Search**

To improve detection accuracy, candidate regions are resized to **128 × 128 pixels** and compared against stored reference templates using normalized pixel similarity. This lightweight verification step helps identify Aadhaar cards, PAN cards, and predefined corporate logos.

**Image Obfuscation**

After a match is confirmed, the detected region is anonymized using Gaussian Blur or a solid masking layer before the document is exported.

# 2. Technical Limitations and Current Workarounds

Like any practical software project, byePII was developed within certain time and resource constraints. Instead of leaving these limitations unresolved, lightweight alternatives were implemented to maintain reliable performance while keeping the application efficient.

## A. LLM-Based Verification

**Limitation**

Traditional NLP models occasionally produce false positives by flagging ordinary words as sensitive information or false negatives by overlooking genuine PII. A Large Language Model (LLM) would provide an additional verification layer by validating detected entities before redaction.

However, integrating an LLM was outside the scope of the current implementation because of API rate limits, token restrictions, and computational cost.

**Current Workaround**

The project uses a rule-based validation layer inside the `ByePIIOrchestrator`.

This validation process:

- Compares detections against a blacklist stored in `outputs/false_positive.json`.
- Ignores predefined table headers and document labels.
- Uses additional regular expression checks to remove obvious false positives before generating the final document.

Although this approach is less flexible than an LLM, it provides predictable performance and requires no external API calls.

---

## B. YOLO-Based Object Detection

**Limitation**

A deep learning object detection model such as YOLO would significantly improve the detection of logos, ID cards, and other visual elements, particularly when they appear rotated, partially visible, or under varying lighting conditions.

However, YOLO introduces large model files, longer startup times, GPU requirements, and additional deployment complexity.

**Current Workaround**

Instead of using deep learning, byePII relies on OpenCV template matching and direct pixel similarity comparisons.

This approach offers several practical advantages:

- Runs entirely on the CPU.
- Requires no pretrained models.
- Starts almost instantly.
- Produces reliable results for known templates such as Aadhaar cards, PAN cards, and predefined company logos.

While it is less flexible than YOLO, it was a suitable trade-off for the current project scope.
